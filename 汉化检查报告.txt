一、检查方法
------------
1) 静态扫描：tools/scan_ui.py
   扫描全部 355 个 .java 源文件里 21 类会直接显示给用户的调用：
   addMessage / addStringField / addNumericField / addCheckbox / addButton /
   addSlider / addChoice / setTitle / new Button / new Label / new Checkbox /
   new JButton / new JLabel / new JCheckBox / new JRadioButton /
   new JMenuItem / new JMenu / new JCheckBoxMenuItem / addTab / setToolTipText /
   new GenericDialog
   再比对语言包是否覆盖。输出 → report_ui.txt

2) 运行时审计：tools/MenuAudit.java
   真正建出菜单对象，逐个读出「显示文本」，判断是否含中文。
   覆盖：主菜单栏全部子菜单、图像窗口右键、选区右键、
        工具栏 7 个弹出菜单、结果/日志窗口菜单栏与右键、ROI 管理器右键。
   这是最可靠的一环 —— 静态扫描看不到 Lang 的前缀匹配与快捷键剥离规则。

四、有意不汉化的部分
--------------------
· 结果表的列名（Area、Mean、Min、Max、Perim.、Feret…）
  以及宏变量名、命令名、插件键值 —— 必须保持英文，否则宏与第三方插件全部失效。
· 第三方插件（.jar）自带菜单项 —— 需要时把其菜单名加进语言包即可。
· 纯技术标识：文件格式后缀、脚本语言名、版本号。

七、窗口布局优化与双窗口架构说明（本次新增）
--------------------------------------------
用户反馈：①状态栏说明文字太靠左、会贴边溢出；②打开图片后为何是"两个窗口"，
希望像普通软件那样工具栏与图片在同一个窗口、图片在下方打开。

1) 状态栏内边距（ij/ImageJ.java）
   给底部状态栏 JLabel 增加左右内边距（各 10×缩放 像素），文字往右挪、不与进度条
   挤压、不贴边"溢出"；保持左对齐，长文本会被裁切而不越出边框。

2) 图片窗口贴附保护（ij/gui/ImageWindow.java）
   打开图片时，强制把图片窗口定位在主窗口（工具栏/菜单）正下方，绝不会浮到工具栏
   上方去遮挡工具，也不会飘到屏幕别处。关闭主窗口时由 ImageJ.quit()→
   WindowManager.closeAllWindows() 自动连带关闭所有图片窗口（该联动原本就有）。

3) 关于"为什么是两个窗口"——这是 ImageJ 1.x 的固有架构，非缺陷
   主窗口（ij/ImageJ.java，一个 Frame）只放菜单+工具栏+状态栏，本身不含图片显示区；
   每张打开的图片都是一个独立的顶层窗口（ij/gui/ImageWindow.java，继承自 Frame），
   自带标题栏、画布、滚动条，由 WindowManager 统一管理。这是 1990 年代 SDI 多窗口
   设计，Fiji / ImageJ2 才有"单窗口模式"。
   · 本次采用的"双窗口·体验优化"方案，能做到：两张窗口视觉风格统一、稳定上下排列、
     关闭联动。但改变不了它是两个独立 OS 窗口的本质——任务栏/Alt+Tab 仍是两个图标，
     图片窗口仍有独立标题栏。
   · 若要"真正单窗口"（一个图标、一个标题栏、图片嵌在主窗口工作区），必须做架构级
     重构：把 ImageWindow 从 extends Frame 改为内嵌容器，并重写 WindowManager、聚焦、
     定位等数十处，可能破坏现有插件/宏、回归测试量大。该方案（标为方案 B）需另行确认
     后再实施，未在本轮执行。

八、语言切换（新增功能）
------------------------
位置：语言（顶级菜单，位于「窗口」与「帮助」之间）
二级两项「中文 / English」，点击立即切换（无对话框、无需确认），写入偏好（gui.language 键）并即时刷新主菜单栏，当前语言带勾选标记；
新打开的窗口/对话框立即跟随新语言，全部界面完全生效请重启程序。
内部命令名仍保持英文，宏与插件不受影响。默认中文。
修复记录：首版偏好键名 language 无点号前缀，触发 Prefs.set 的
"Key must have a prefix" 异常导致切换失败；已改为 gui.language 并验证
中→英→中往返切换正常。
